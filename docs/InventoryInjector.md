# InventoryInjector compatibility

InventoryInjector's [IconSetter hook](https://github.com/Exit-9B/InventoryInjector/blob/52cc4cb30f2ec09eba104606c8cdd17050c3a2bf/src/Hooks/IconSetter.cpp) wraps `InventoryIconSetter.processList`. It prepares entries, calls the previous list processor, and applies custom data and color handling. Direct calls to the private `processEntry` method bypass that wrapper. A changed item consequently receives the standard icon but misses the custom override; reopening the menu runs the full list processor again.

The incremental path calls the installed icon and property `processList` methods in their normal order with the original processor as `this`. The temporary argument exposes one changed-entry array through both `entryList` (SkyUI) and `_entryList` (InventoryInjector). The array holds references to the actual current entries, not copies. Native item indices are preserved, and the live menu list is never replaced with the subset. This retains the examined hook's pre-processing, chained callback, and custom-data passes while keeping their cost proportional to the changed batch. The item-card processor continues to receive the complete real list because its request callback relies on native indices.

The relevant SkyUI contracts are [InventoryIconSetter](https://github.com/schlangster/skyui/blob/master/src/ItemMenus/InventoryIconSetter.as) and [PropertyDataExtender](https://github.com/schlangster/skyui/blob/master/src/Common/skyui/props/PropertyDataExtender.as). Both list methods iterate `entryList`. This subset contract does not establish compatibility with arbitrary processors that depend on other menu methods or whole-list aggregates.

Separately, object-specific collection also increments the enumeration counter. That counter therefore cannot distinguish full rebuilds from partial updates. The refresh hook records whether `pendingUpdateObjects` is empty before the engine consumes it. Only a full rebuild permits replacement-object cache reuse; a partial update's newly constructed entries remain dirty even if their primitive fields happen to match.

Static review covers both array aliases, processor order and receiver, entry identity, native indices, failure fallback, and the rebuild-mode guard. Runtime verification remains necessary with InventoryInjector and B.O.O.B.I.E.S: equip and unequip affected items, change selection/category, reopen the menu, and check custom labels, sources, colors, and mouse preselection. The same processor path must also work with SkyUI alone; vanilla uses its existing separate frontend path.
